# design-kit-v2 — план пересборки

Пересборка дизайнерского стартера с нуля, файл за файлом. Старый шаблон
(`d:\Git\product-design-starter`) остаётся боевым и не трогается — этот репо
живёт рядом как параллельный эксперимент и мигрирует, только когда выиграет по цифрам.

Дата старта: 2026-08-26.

## Зачем

Замер v1 на 2026-08-26 — что дизайнер платит ещё до первого своего слова:

| Что грузится всегда | Размер | ≈ токенов |
|---|---|---|
| AGENTS.md + CLAUDE.md | 9.5 КБ | 2 400 |
| frontmatter 20 скиллов | 8.6 КБ | 2 100 |
| 14 команд | 2.3 КБ | 570 |
| **итого накладных** | **20 КБ** | **≈5 000** |

Плюс системный промпт Claude Code (~11k) и MCP-инструменты. Пустое «привет» стоит ~17k.
Дальше: refs скиллов до 52 КБ (ux-write/ux-check), 20 КБ (screen-map), `xui-toolkit-v2/SKILL.md`
на 14.7 КБ грузится целиком при активации. 93 файла в `.claude/`, 630 КБ скриптов.

Цель v2 — не «сделать красивее», а **знать цену каждого файла** и держать её осознанно.

## Четыре принципа

1. **Кирпич = коммит = замер.** Ничего не кладётся «на будущее». Файл появляется только
   после того, как реальный прогон показал, что без него агент ломается.
2. **Правило живёт в харнессе, а не в прозе.** Хук, линтер, схема, скрипт — сначала.
   Текст в AGENTS.md — последнее средство, для того что нельзя проверить программой.
   Каждое правило, переехавшее из прозы в код, обязано быть видно в замере как минус токены.
3. **Контекст — бюджет.** Всё, что грузится всегда, конкурирует за одно окно.
   Что грузится по требованию — не бесплатно, но дёшево. Различие проектируем явно.
4. **Дизайнер ведёт.** Агент предлагает и задаёт один вопрос за раз, а не читает лекции.

## Как замеряем

Источник правды — транскрипт сессии Claude Code
(`~/.claude/projects/<slug>/<session>.jsonl`), там в каждом ответе лежит `usage`.
Скрипт `scripts/ctx.mjs` читает последнюю сессию и печатает:

- **BASE** — стоимость первого ответа сессии = цена «просто открыть проект».
- **PEAK** — максимум занятого окна за сессию.
- **TASK** — дельта на конкретную задачу (от её первого сообщения до последнего).
- **ТОП-потребители** — какие tool_result / файлы съели больше всего.

Каждый кирпич дописывает строку в `docs/ctx-log.md`: кирпич → сценарий → BASE/PEAK/TASK.
Никакого ручного счёта и никаких оценок «на глаз».

## Кирпичи

| # | Кирпич | Что кладём | Чем проверяем | Что решаешь ты |
|---|---|---|---|---|
| К0 | Весы | `scripts/ctx.mjs`, `docs/ctx-log.md` | прогон на пустом репо → BASE «голого» Claude Code | формат отчёта, что считаем метрикой |
| К1 | AGENTS.md-минимум | один `AGENTS.md` ≤ 800 токенов | BASE до/после | язык файла, что в нём обязано быть |
| К2 | Вход и три режима | скилл `start` + один вопрос | прогон «привет» в трёх режимах | формулировки трёх вариантов |
| К3 | Стейт как данные | `state.json` + `npm run state` | прогон «продолжаем» — агент не читает прозу | какие поля живут в стейте |
| К4 | Прототип-минимум | Vite+React+XUI, один пустой экран | прогон «сделай экран по макету» | стек и что значит «пусто» |
| К5 | Харнесс вместо прозы | хуки: guard путей, eslint-on-write, DS-правила | AGENTS.md худеет, BASE падает | какие правила жёсткие, какие советы |
| К6 | Режим A: конвейер | стадии + один ref на стадию | прогон «новая фича с PRD» | сколько стадий выживает |
| К7 | Screen map | только если К4/К6 показали боль | прогон «покажи карту экранов» | нужен ли вообще |
| К8 | DS-мост | resolution order как проверка, не как текст | прогон «сделай компонент» | строгость гейта |
| К9 | Setup / update | как это ставится и обновляется | установка в чистую папку | канал доставки |

Порядок К0→К5 жёсткий. К6–К9 пересматриваем после К5 — к тому моменту цифры
могут сказать, что половина не нужна.

## Три режима входа (К2)

Агент на первом сообщении задаёт **ровно один вопрос** и запоминает ответ в стейте:

- **A. Полный продуктовый цикл** — собираем PRD, идём по стадиям. Как в v1.
- **B. Сначала прототип, документы потом** — стадии пропускаем, агент помечает долг
  в стейте и сам возвращается к нему, когда прототип встанет на ноги.
- **C. Просто экран(ы) из Figma** — никакой продуктовой обвязки, только вёрстка на DS.

Режим определяет, какие скиллы вообще существуют для сессии: в C не должно грузиться
ничего продуктового, и это должно быть видно в замере.

## Что осознанно НЕ переносим из v1 сразу

Не выброшено — отложено до доказательства нужности реальным прогоном:

- 8 сабагентов (23.7 КБ) — сначала проверим, справляется ли основной агент.
- 14 команд, дублирующих скиллы, — скилл уже вызывается по описанию.
- `ux-write` / `ux-check` с 52 КБ общих рефов — кандидат №1 на переезд в линтер.
- `xui-toolkit-v2/SKILL.md` (14.7 КБ) — резать на части, грузить нужное.
- 10 стадий 00–09 — сколько из них реально проходит дизайнер, столько и оставим.
- Context App, promote/xui-vibe, brownfield-логика, миграции.
